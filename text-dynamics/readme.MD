# Спецификация формата данных: Text Dynamics JSON (TDJ)

Формат для визуализации истории текста. Текст представлен как набор версий,
между которыми лежат последовательности атомарных операций над **плоским потоком
токенов**.

В этой редакции TDJ:
- `versions[].text` — плоский массив токенов;
- граница абзаца кодируется **токеном-разделителем** `meta.para` (по умолчанию `"\n\n"`);
- операции адресуются одним индексом `i` (в плоском потоке).

---

## 1. Общая структура

TDJ может быть представлен в двух режимах: **линейном** (для простого плеера) и
**графовом** (для ветвлений).

### 1.1. Линейный режим (цепочка версий)

    {
      "meta":     { ... },
      "versions": [ ... ],
      "ops":      [ ... ]
    }

Инвариант:

> применение `ops[ versions[i].from ... versions[i+1].from - 1 ]`
> к `versions[i].text` даёт **ровно** `versions[i+1].text`.

Этот режим совместим с плеером, где версии идут по одной шкале.

### 1.2. Графовый режим (ветвления)

    {
      "meta":     { ... },
      "versions": [ ... ],
      "edges":    [ ... ]
    }

Где `edges[]` описывает переходы между версиями. Инвариант для каждого ребра:

> применение `edge.ops` к `versions[edge.from].text`
> даёт **ровно** `versions[edge.to].text`.

Примечание: текущий UI может поддерживать только выбранную “основную” цепочку,
но формат данных допускает несколько переходов от одной версии.

## 2. Секция `meta`

| Поле | Тип | Описание |
|---|---|---|
| `work` | string | Автор и произведение |
| `part` | string | Структурная единица: действие, явление, глава, строфа |
| `src` | string | Печатный источник, по которому выверены версии |
| `note` | string | Методологическая оговорка (обязательна к показу в интерфейсе) |
| `para` | string | Токен-разделитель абзацев в `versions[].text` (по умолчанию `"\n\n"`) |

`meta.para` может быть любым токеном-строкой, выбранным генератором. Он:
- присутствует внутри `versions[].text`;
- участвует в diff как обычный токен;
- может вставляться/удаляться/заменяться операциями.

---

## 3. Секция `versions`

Массив версий в хронологическом порядке (в графовом режиме это “порядок
показа”, а не единственный путь редактирования).

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | string | да | Короткий ключ версии (`v1`, `v1r`, `p1836`) |
| `title` | string | да | Заголовок для шкалы |
| `date` | string | да | Дата как в источнике (“осень 1835”) |
| `ts` | string | да | ISO-дата для позиционирования (“1835-10-01”) |
| `src` | string | да | Свидетель: архив, шифр, сигла |
| `note` | string | нет | Комментарий к версии |
| `from` | number | линейный | Индекс в `ops`, с которого начинается переход **от** этой версии к следующей |
| `text` | array | да | Снапшот: плоский массив токенов |

### 3.1. Поле `text`

`versions[].text` — плоский массив токенов (строк). Абзацы разделяются токеном
`meta.para`.

Пример:

    "text": [
      "ЯВЛЕНИЕ", "VI", ".", "\n\n",
      "Городничий", ".", "Осмелюсь", "представить", "вам", ":",
      "жена", "и", "дочь", "."
    ]

Пробелы не хранятся в данных и не считаются значимой частью diff (см. §6.1).

---

## 4. Секция `ops` (линейный режим) и `edges[].ops` (графовый режим)

Операции применяются к плоскому массиву токенов.

| Поле | Тип | Описание |
|---|---|---|
| `i` | number | Индекс токена в текущем состоянии текста (логический индекс среди “живых” токенов) |
| `d` | number | Сколько токенов удалить, начиная с `i` |
| `v` | array | Какие токены вставить в позицию `i` |
| `c` | string | Комментарий операции (tooltip) |

Комбинации:

    { "i": 120, "d": 1 }                           удаление
    { "i": 120, "v": ["очень"] }                   вставка
    { "i": 120, "d": 2, "v": ["Мы","с","своей"] }  замена
    { "i": 55,  "c": "в рукописи описка" }         примечание (текст не меняет)

Поскольку абзац — это токен `meta.para`, абзацные изменения выражаются обычными
операциями над этим токеном:

    { "i": 40, "d": 1 }            удалили meta.para → абзацы слились
    { "i": 40, "v": ["\n\n"] }     вставили meta.para → абзац разбит

Отсутствующие ключи не пишутся (ни `null`, ни `0`).

## 5. Реконструкция состояния

### 5.1. Линейный режим

Чтобы получить текст на позиции N шкалы процесса:

    const ver = последняя версия, у которой from <= N;
    let tokens = deepCopy(ver.text);
    for (let k = ver.from; k < N; k++) applyOp(tokens, ops[k]);

### 5.2. Графовый режим

Чтобы получить текст версии `to` из версии `from` по ребру:

    let tokens = deepCopy(versions[from].text);
    for (const op of edge.ops) applyOp(tokens, op);

### 5.3. Применение операции

    function applyOp(tokens, o) {
      if (o.d == null && o.v == null) return;     // примечание
      tokens.splice(o.i, o.d ?? 0, ...(o.v ?? []));
    }

### 5.4. Отложенное удаление (для подсветки)

Для анимации удалённые токены можно не удалять физически, а помечать как `del`.
Тогда индекс `i` разрешается через “живые” токены (те, что не `del`).

---

## 6. Визуализация

### 6.1. Восстановление пробелов

Пробелы не хранятся в данных. Визуализатор восстанавливает пробелы по правилу
(например как в текущем UI: пробел ставится почти всегда, кроме пунктуации и
некоторых открывающих знаков).

Абзацы для рендера получаются разделением потока `versions[].text` по токену
`meta.para`.

---

## 7. Ограничения

1) Перемещения не поддержаны (перенос = delete + insert).
2) Точность whitespace ограничена: количество пробелов не считается правкой;
   значим только токен-разделитель абзаца `meta.para`.
3) Формат допускает ветвления (графовый режим), но конкретный визуализатор может
   отображать лишь выбранную цепочку.
